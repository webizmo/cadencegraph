# Competitive landscape and the alpha.5 authoring target

Research date: **22 October 2026**. This comparison uses the official sources linked below and the alpha.4 source/README. It is a capability review, not a hands-on benchmark of competitors. Plan availability, regional availability and paid entitlements were not tested. Features missing from a source are **unknown**, not proof that the product lacks them. This document records the implementation target; release verification is recorded separately in [verification](verification/README.md).

## The problem to solve

Alpha.4 can revise and render its example, but the editor cannot create a new scene sequence. Its open JSON format and code registry allow developers to author other films; that does not satisfy a person who opens the editor to make a different film. Scene creation, duplication, removal and ordering must be part of the product, together with adding content and controlling when it appears.

The immediate target is a **local motion-video authoring studio** for short explainers, announcements, lessons and product stories. A user should start from a blank project, assemble their own sequence and export it in English/Turkish and landscape/portrait. This is a concrete expansion beyond the supplied three scenes. It is not a claim of parity with a mature nonlinear editor or animation package.

## A defensible product direction

The product hypothesis is **editable structure with predictable revisions**: one versioned project connects scenes, sentences, media and language variants; people can make a local visual decision; subsequent reviewed AI proposals must respect it. The value is the combined workflow and its understandable controls. The research does not establish that no competitor can implement the same behavior.

Preserve these existing contracts as authoring expands:

- Human and AI edits use atomic core transactions; invalid edits cannot leave a partially changed project.
- Protected ratio-specific layout remains protected, including during structural edits that could otherwise delete the protected object.
- Stale AI proposals are rejected. Applying a proposal is an explicit user action with affected scenes/outputs visible.
- Stable IDs and valid sentence references survive duplication and reordering. Imported JSON is untrusted and validated.
- Preview and export share deterministic composition; localization and new scene structure do not fork into separate render implementations.

## Alpha.5 implementation scope

These are acceptance targets, not declarations that the code has already passed them.

| Workstream | Required authoring behavior | Acceptance evidence |
| --- | --- | --- |
| **Blank project and scenes** | Create a named project; add a blank scene or a reusable scene design; rename, duplicate, delete and move scenes. Empty states explain the next action. Undo/redo restores structure as well as text. | A real browser creates an original sequence whose scene count/order/content differ from the starter. Duplication produces fresh IDs and valid links. |
| **Content and media** | Add/remove/duplicate supported layers. Edit text, layout and supported styling; select local image/video media and sentence audio. Manage sentence text and duration for the selected language. | Import valid image, video and audio assets; inspect their placement in preview and exported MP4. Missing/unsupported assets produce actionable errors. |
| **Motion and time** | Expose existing entrance choices and supported timing offsets in the inspector, alongside scene/sentence duration and timeline feedback. Clearly label these as preset motion and timing controls. | Change when an element appears and its entrance; scrub, play and inspect rendered frames around the event. Duration edits remain valid in both languages. |
| **Reusable design** | Provide several editable scene designs and brand/palette choices. Blank scenes remain available. Duplicating a customized scene reuses actual user work. | Build an original film using both blank and preset scenes, replace preset copy/media and modify styling. A preset is an editable starting point, not a locked film. |
| **Useful AI** | Let Claude propose supported structural/content/timing changes, including creating scenes where implemented. Show operation summaries before application; keep schema, revision and protection validation. No model-generated executable code enters project JSON. | Test valid and invalid structural proposals, protected-layout conflicts and stale revisions. Distinguish fixture tests from a real authenticated Claude call. Never represent canned output as a provider response. |
| **Real delivery** | Save/reopen the authored project and render EN/TR × 16:9/9:16 through the existing local pipeline. Preserve compatibility with alpha.4 projects. | Desktop and narrow/mobile browser acceptance, core/API checks, four real MP4s from the new authored example, media/audio inspection and public CI/release evidence. |

## Claims and limits at release

Only promote a target to a release claim when its tests and real export evidence exist. The important proof is an original film created through the editor, not a renamed starter or another ratio export of the same three scenes. Include a reproducible source project and describe which media are fixtures, generated artwork or actual narration.

Even after this scope passes, use **motion-video authoring alpha** rather than “complete video editor.” Full property keyframes/curves, arbitrary code import, multitrack audio mixing, source-video audio handling, transcription, speech/image/video generation, automatic translation, remote asset search, cloud render farms, collaboration and mobile-device certification require their own implementation and acceptance. A responsive Chromium test is not a physical iPhone or Android test. A successful Claude fixture is not a live-provider acceptance.

Do not claim faster rendering, better design quality, lower total cost, broader format support, market leadership or competitor feature parity without a separately specified benchmark. This review establishes an authoring baseline and a direction for evidence-backed differentiation; it does not rank the products overall.
